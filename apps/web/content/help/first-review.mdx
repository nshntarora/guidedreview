# Your first review

From a normal GitHub PR page to a structured walkthrough in a few clicks. This page is the **Chrome extension** path. For a local branch, commit, or working tree, use the [CLI](/docs/cli) instead. If the extension isn’t installed yet, start with [Chrome Extension](/docs/chrome-extension).

<TocCard toc={toc} />

## Open a pull request

Open a pull request on `github.com`. You can start from Conversation, Files changed, or Commits.

If the button is missing, see [Troubleshooting](/docs/troubleshooting#no-start-guided-review-button).

## Start Guided Review

Click **Start Guided Review** on the PR page. The overlay opens and loads the diff.

With an [AI provider configured](/docs/configure-provider), review units appear as your model organizes related changes. Without a key, you can read one unit per changed file, in diff order.

You can also start from the **Guided Review toolbar icon** while a PR tab is active. For pinning the icon or opening reviews automatically on Files changed, see [Chrome Extension](/docs/chrome-extension#after-install).

Connection failures after a key is set: [Troubleshooting](/docs/troubleshooting#provider-and-api-key).

## Follow the Walkthrough

Start with the change summary, then follow the review units. Each unit brings related changes together. See [Reading the overlay](/docs/reading-the-overlay) for a map of the controls.

For each unit you can:

- Read the unit’s title and guidance (take summaries with a grain of salt — see the [FAQ](/docs/faq#does-the-ai-approve-prs))
- See the linked hunks from the real diff (default **unified** view; switch with `v u` / `v s`, or the toolbar — choice is remembered). [Images and binary files](/docs/images-and-binaries) use a preview or empty state instead of a line patch.
- Move next / previous with the footer or [keyboard shortcuts](/docs/keyboard-shortcuts)

The model chooses the order and writes guidance. The code you read comes from the real diff. Check the guidance against the code; you decide whether the change is correct. [How a review plan works](/docs/how-it-works) explains how units are built and validated.

## Search the diff

Press `⌘/Ctrl` + `F` to search file paths and code across the whole PR diff. Pick a result to jump to the unit that owns that match. Full behavior: [Keyboard shortcuts → Diff search](/docs/keyboard-shortcuts#diff-search).

## Leave comments and submit

As you walk:

1. Press `c` to enter comment mode, select lines, and [draft line comments](/docs/leave-comments). Drafts stay local until you submit ([privacy](/docs/privacy-and-data#what-stays-local)).
2. When you’re ready, press `⌘/Ctrl` + `Enter` (or use **Submit Review**) to choose Comment / Approve / Request Changes and [send the review](/docs/submit-review).

Submit needs [GitHub connected](/docs/connect-github). Following the walkthrough and drafting do not. Full shortcut list: [Keyboard shortcuts](/docs/keyboard-shortcuts).

## Resume later

You can switch between a PR’s Conversation and Files changed tabs and resume the same review. Your progress and drafts remain available until the browser session ends. For storage limits and clearing a session, see [Troubleshooting](/docs/troubleshooting#session-and-resume).

If something fails mid-flight, see [Troubleshooting](/docs/troubleshooting).

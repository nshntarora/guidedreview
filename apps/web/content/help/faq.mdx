# FAQ

Short answers to the questions people ask before and after install. Longer how-tos live in the rest of the docs — start from the [Introduction](/docs) if you’re new.

<TocCard toc={toc} />

## How does it work?

Guided Review parses a real unified diff, optionally calls **[your AI provider](/docs/configure-provider)** for ordered **review units** (or walks **file by file** if no key is set), and shows them in a keyboard-first overlay mapped back to the real hunks.

- **GitHub PRs:** [Install the Chrome extension](/docs/chrome-extension), open a PR, click **Start Guided Review** — [Your first review](/docs/first-review). Optionally [comment](/docs/leave-comments) and [submit](/docs/submit-review).
- **Local git:** run `npx @guided-review/cli`, pick a scope, optionally **Structure with AI** — [CLI](/docs/cli).

Pipeline detail: [How a review plan works](/docs/how-it-works). Keyboard-first path: [Keyboard shortcuts](/docs/keyboard-shortcuts).

## Extension or CLI?

| Need                                       | Use                                                    |
| ------------------------------------------ | ------------------------------------------------------ |
| Review a PR already on `github.com`        | [Chrome extension](/docs/chrome-extension)             |
| Review before opening a PR / no PR yet     | [CLI](/docs/cli)                                       |
| Submit Comment / Approve / Request Changes | Extension (+ [GitHub connected](/docs/connect-github)) |
| Turn line notes into a coding-agent prompt | CLI [Generate Prompt](/docs/generate-prompt)           |

Same clustering engine either way. You can use both on the same change over time (local pass, then PR pass).

## Do you track anything?

The **extension** and **CLI** do not track review activity and do not talk to Guided Review servers — only your AI provider (and GitHub for the extension’s fetch/submit paths). The **marketing site** uses an analytics service for page views and a few CTA clicks. Full breakdown: [Privacy & data](/docs/privacy-and-data).

## Is it free forever?

Forever is a long time. It’s free while it can be maintained for free. If demand grows and maintenance can’t stay free, something for compensation might show up later. It’s [open source](https://github.com/nshntarora/guidedreview) — you can fork it if you need to. Getting set up costs only your own provider usage ([Configure AI provider](/docs/configure-provider)).

## Will this run up my API bill?

Annotating with a provider configured makes **one call per diff chunk** — small diffs are usually a single call; large ones are [split by file](/docs/how-it-works#chunking-large-diffs) (~60k characters per chunk), so cost scales with diff size and [model](/docs/configure-provider#pick-a-model). A small change on a cheap model is fractions of a cent; a huge monorepo diff on a frontier model is not.

On the **CLI**, that call only runs when you click **Structure with AI**. On the **extension**, it runs when you start a review with a key configured.

You’re paying your provider directly — usage shows up on their dashboard, not ours. Guided Review does not meter or resell LLM traffic. Walking units, searching, drafting comments/notes, submitting to GitHub, and Generate Prompt do **not** call the model again.

## Can I use it without an API key?

Yes, partially. Without a key you still get the overlay, real diff, [file-per-unit plan](/docs/how-it-works#without-a-provider), and [diff search](/docs/keyboard-shortcuts#diff-search). On the extension you can [draft comments](/docs/leave-comments); on the CLI you can leave notes. You won’t get AI clustering or unit summaries until you [configure a provider](/docs/configure-provider). [Submit](/docs/submit-review) still needs [GitHub connected](/docs/connect-github), not an LLM key.

## Does the AI approve PRs?

No. The model clusters and orders changes and writes short guidance ([How a review plan works](/docs/how-it-works)). You read the code. On GitHub, **you** [submit](/docs/submit-review) approve / comment / request changes. The CLI never posts a GitHub review. Take unit summaries with a grain of salt.

## Which AI providers?

Anthropic (Claude), OpenAI, and Grok (xAI). You bring your own API key. The CLI can also reuse a coding agent already on the machine (Claude Code, Codex, or Grok). Setup and model list: [Configure AI provider](/docs/configure-provider). Connection failures: [Troubleshooting](/docs/troubleshooting#provider-and-api-key).

We’ll keep adding more providers — [request one on the repo](https://github.com/nshntarora/guidedreview), or open a PR that adds yours.

## Do I need GitHub auth?

Not to generate a plan or walk units ([Your first review](/docs/first-review), [CLI](/docs/cli)). Yes, if you want to [submit a review](/docs/submit-review) (line comments and overall decision) from the **extension**. [Drafting comments](/docs/leave-comments) works offline of GitHub auth. The CLI never uses GitHub OAuth. Scopes, SSO, and disconnect: [Connect GitHub](/docs/connect-github).

## Does it work outside github.com?

The **extension** content script targets **`https://github.com/*` only** — public and private repos on github.com, not GitHub Enterprise Server, GHEC enterprise hosts with a different hostname, or other forges. The **CLI** reviews any local git repo on your machine — no GitHub host required. If you need the extension on another host, open an issue or PR on the [repo](https://github.com/nshntarora/guidedreview).

## Where is the code?

[github.com/nshntarora/guidedreview](https://github.com/nshntarora/guidedreview) (Apache-2.0). Issues and PRs welcome when something’s wrong or unclear. Install the [Chrome extension](/docs/chrome-extension) from the Web Store, or the CLI via `npx @guided-review/cli`.

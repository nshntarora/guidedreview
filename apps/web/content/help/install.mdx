# Install Guided Review

Two ways in: the **Chrome extension** for GitHub pull requests, and the **CLI** for local branch, commit, or working-tree diffs. Same review engine; pick the host that matches the change you’re reviewing. For the “why,” see [Why](/docs/why); for the product map, see the [Introduction](/docs).

## Chrome extension

Guided Review runs as a Chrome Manifest V3 extension on `github.com` pull requests.

### Chrome Web Store

1. Open the <a href={CHROME_WEB_STORE_URL}>Guided Review listing</a> on the Chrome Web Store.
2. Click **Add to Chrome** and confirm.
3. Pin the extension from the puzzle-piece menu so the toolbar icon stays visible — unpinned extensions are easy to forget.

> **Site shortcuts.** On [guidedreview.dev](https://guidedreview.dev), `⌘/Ctrl` + `E` opens the Chrome Web Store listing; `⌘/Ctrl` + `I` jumps to the Install section — see [Keyboard shortcuts](/docs/keyboard-shortcuts#marketing-site).

### Load unpacked (development)

For local builds and contributors:

1. Clone the [repository](https://github.com/nshntarora/guidedreview).
2. From the monorepo root, install and build the extension:

```bash
pnpm install
pnpm build:extension
```

3. Open `chrome://extensions`, enable **Developer mode**, and click **Load unpacked**.
4. Select **`apps/extension/dist`** — never a root-level `dist/` if one exists from an older layout.
5. After code changes, run `pnpm build:extension` again, then hit **Reload** on the extension card and refresh the GitHub PR tab.

> **Dev HMR.** `pnpm dev` / `pnpm dev:extension` serves Vite HMR on port **5173**, but Chrome still loads the built files under `apps/extension/dist`. Rebuild (or rely on the dev pipeline that writes there) and reload the extension when behavior looks stale. More on stale builds: [Troubleshooting](/docs/troubleshooting#load-unpacked-stale-build).

### After install

Chrome opens a short **welcome** page on first install (pin → connect provider → open a PR). You can also:

1. Open the extension **Options** page (right-click the toolbar icon → Options, or open it from `chrome://extensions`).
2. [Configure an AI provider](/docs/configure-provider) and save your API key (optional for a [file-by-file walk](/docs/how-it-works#without-a-provider); required for clustering and summaries).
3. Optionally [connect GitHub](/docs/connect-github) if you want to [submit reviews](/docs/submit-review) from Guided Review.
4. Open a PR and follow [Your first review](/docs/first-review).

**Ways to start a review** once you’re on a PR tab:

- Click **Start Guided Review** on the page.
- Click the **toolbar icon** — on a PR it starts (or resumes) the review; off a PR it tells you to open one.
- Enable **Automatically open on Files changed** in Options if you want that tab to open Guided Review for you.

Keys and tokens stay on your machine — details in [Privacy & data](/docs/privacy-and-data). If the **Start Guided Review** button never appears, see [Troubleshooting](/docs/troubleshooting#no-start-guided-review-button).

## CLI

For local git work — before you open a PR, or when there isn’t one:

```bash
npx @guided-review/cli
```

Requires **Node.js 22+**. The published package is `@guided-review/cli`; the binary is `guidedreview`. `npx guided-review` (unscoped, hyphen) is a different tool.

The CLI starts a localhost server, opens the browser UI, and walks the same kind of review units as the extension. Diff scopes, flags, Settings, and **Generate Prompt** are covered in [Review local changes](/docs/local-review). Provider setup for the CLI (env, config file, or a coding agent already on the machine): [Configure AI provider](/docs/configure-provider#cli).

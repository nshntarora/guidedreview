# Connect GitHub and understand OAuth permissions

Connecting GitHub is **optional** for reading a PR and generating a guided plan in the **Chrome extension**. It is required if you want to **[submit a review](/docs/submit-review)** (line comments, approve, request changes) from the overlay. The [CLI](/docs/cli) does not use GitHub OAuth — local notes stay on your machine.

You still need an [AI provider](/docs/configure-provider) to build an AI plan. Auth for GitHub and your LLM are separate.

<TocCard toc={toc} />

## Why connect GitHub?

Without GitHub auth, Guided Review can still:

- Detect the PR from the page
- Fetch the diff path the extension uses for review planning
- Stream a plan and [walk units](/docs/first-review)
- [Draft line comments](/docs/leave-comments) **locally** (they stay in the session until submit)

With auth, Guided Review can also post those drafts and your overall review decision through the GitHub API as you — see [Submit a review](/docs/submit-review).

Also answered in the [FAQ](/docs/faq#do-i-need-github-auth).

## Device flow

Guided Review uses GitHub’s **device OAuth** flow from the options page (and prompts in the overlay when submit needs a token):

1. Open Options → GitHub section (or the connect modal when [submitting](/docs/submit-review#open-submit-review)).
2. Start the device flow and open the verification URL GitHub shows.
3. Enter the code and approve access in the browser.
4. Return to the extension — tokens are stored locally for subsequent API calls.

Stuck mid-flow? [Troubleshooting → GitHub connect and submit](/docs/troubleshooting#github-connect-and-submit).

## What we request

GitHub OAuth scopes are named permissions an app requests to act on your behalf. Guided Review requests `repo` and `read:user` through device flow:

| Scope       | Why                                                                                             |
| ----------- | ----------------------------------------------------------------------------------------------- |
| `repo`      | Read PR context and write review comments on public **and** private repositories you can access |
| `read:user` | Show who’s connected in the UI                                                                  |

Classic OAuth has no finer “only review private PRs” slice, so `repo` is intentionally broad. Tokens stay in extension storage. They are not sent to Guided Review servers — there are none for the product path. Full data picture: [Privacy & data](/docs/privacy-and-data).

**The scope allows more than the review actions listed above.** GitHub defines `repo` as broad repository access, including code writes and managing collaborators and webhooks. `read:user` permits reading profile details. A scope cannot give the app rights your account lacks. See GitHub’s [OAuth scope reference](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps) for the full permissions.

For example, connecting to submit a review on one private PR does not limit the OAuth grant to that PR. Review the authorization screen and your organization’s policy before granting access. If the broad scope is unsuitable, leave GitHub disconnected and submit your review on github.com. You can still use the extension’s local drafts and walkthrough without this OAuth connection.

> **Org policies.** Some organizations require approving third-party OAuth apps. If device flow fails with an org restriction, approve the app in GitHub settings or complete the review on github.com itself.

## Private repos and org SSO

- **Private PRs** — Submit works when your GitHub user already has access and the token is authorized for that repo/org.
- **SAML / SSO orgs** — After connecting, GitHub may still require you to **authorize the token for SSO**. Open GitHub → **Settings → Applications**, find the Guided Review authorization, and authorize access for the organization. Without that step, submit often fails with not-found or access errors even though you can open the PR in the browser.
- If access still fails after SSO, disconnect and connect again in Options, then re-authorize SSO if prompted.

Step-by-step recovery: [Troubleshooting → Private repos and SSO](/docs/troubleshooting#private-repos-and-sso).

## Disconnect

Use **Disconnect** / sign-out in Options to clear stored GitHub credentials. You can still [generate guided plans](/docs/first-review) and [draft comments](/docs/leave-comments); only [submit from Guided Review](/docs/submit-review) stops working until you connect again.

Disconnect removes the token from this extension’s storage. It does not revoke the app’s authorization on GitHub.

### Revoke access on GitHub

To withdraw the OAuth grant as well:

1. Open GitHub **Settings → Applications → Authorized OAuth Apps**.
2. Find the Guided Review authorization and choose **Revoke** for that app. Avoid **Revoke all** if you want to keep other apps connected.
3. Use **Disconnect** in the extension’s Options to clear its saved credentials too.

GitHub’s [authorized-app instructions](https://docs.github.com/en/apps/oauth-apps/using-oauth-apps/reviewing-your-authorized-oauth-apps) show where to find the controls. [Revoking the authorization invalidates its associated tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/token-expiration-and-revocation), so submitting through Guided Review will require connecting again. Reviews already posted remain on GitHub; local drafts are not submitted by revoking access. Your AI provider key is separate and is unchanged.

# AI code review that does not auto-approve

I don't want the model that explains a change to decide whether I should merge it.

AI can group related hunks, suggest a reading order, and add commentary. I still want a person to choose Comment, Approve, or Request Changes after reading the code.

Here's why. You read “invalid input is rejected” in a summary. There's a passing test with a similar name. It feels answered.

Which input? A missing field? An empty string? A value outside a range?

The summary has compressed three questions into one reassuring sentence.

## Read the rejection branch before trusting the summary

I'd start with the condition in the handler. Work out exactly what reaches the rejection path, then read any caller that depends on the old behavior.

Now look at the test. Rejecting a missing field doesn't establish what happens to an empty string. Its name can be broader than its assertion.

“Should an empty string be rejected too?” is a useful comment beside that condition. Someone can answer it. Another summary won't settle the requirement.

This applies when you're reviewing a teammate's PR and when you're checking your own agent-written work. The review standard doesn't change with the author.

## What Guided Review lets the model do

Guided Review parses the real diff into files and hunks. The model groups those hunks into ordered review units and adds commentary. The overlay resolves its references against the parsed diff and [drops invalid hunk identifiers](/docs/how-it-works).

The model never supplies the code shown in the overlay. Production changes and tests appear as separate units, so you can read the behavior before the test's account of it. The [AI-generated PR guide](/guides/review-ai-generated-pull-request) follows that order through a timeout change.

Commentary can still be wrong. I can validate a hunk ID. I can't validate a product decision that way.

## What the reviewer still has to check

Follow the inputs, defaults, failure paths, authorization boundaries, callers, and outputs. Ask whether the test would fail for the mistake you have in mind.

A green suite tells you the selected examples pass. If no example covers an empty string, it hasn't answered the empty-string question.

The model's useful job here is to get related code in front of me in an order I can follow.

## An Approve button still needs a person

After an optional GitHub connection, the [Chrome extension](/docs/chrome-extension) can [submit Comment, Approve, or Request Changes](/docs/submit-review). You select the outcome and what to send. Guided Review never auto-approves or rejects a PR.

The [CLI](/docs/cli) doesn't submit GitHub reviews. Local notes stay with the running session, and Generate Prompt formats them for copying into a coding agent. AI structuring is opt-in. Both hosts support your own Anthropic, OpenAI, or Grok key, with no Guided Review backend receiving the diff.

If you need automated findings on every PR or a required merge check, you need a tool that does those jobs. For a tiny patch, the normal diff may be enough.

Before I approve this validation change, I want an answer about the empty string.
